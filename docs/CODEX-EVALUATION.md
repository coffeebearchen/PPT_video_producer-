## 一、总体结论

**需要调整。** 同意以 VibeMotion 为唯一视频渲染执行器，把旧引擎的固定页式能力迁为一种编排模式。切换前应先保护两条链路的产物与发布历史，验证干净环境可运行，并补齐旧链路实际使用的页面、批量、审批和渠道能力。

本次以 Git `5fd6b73` 的工作区为基线，逐文件读取了 283 份源码、配置、脚本、样例及文档，其中包括 `docs/` 下全部 47 份 Markdown、根目录规则与版本记录，以及 11 份本地 renderer 分镜。对 147 个 JS、TS 和 HTML 文件做了静态结构扫描，交叉核对下表的关键实现。扫描范围是当前工程源码及文档，安装依赖、历史发布包、媒体二进制、数据库内容和真实凭据未纳入。 [评审指令](CODEX-EVALUATE-PLAN.md) · [被评方案](EVALUATION-PLAN.md) · [统一行动方案](ACTION-PLAN.md)

## 三、六个问题的回答

### 1. 阶段顺序

主顺序是**隔离基线 → 发布和任务边界 → 两条样本链路 → 统一工作台与兼容 → 切默认 → 退役**。四页原型可在基线和最小接口明确后离线并行。涉及审批、发布和旧数据切换的接入等地基验收通过。

- **隔离和恢复先于接入。** `STUDIO_DATA_DIR` 只覆盖部分运行路径。现有备份与恢复脚本硬编码 `data/`，音乐索引文件名不配对。账号与分组 E2E 脚本请求 4310 并直接打开默认库做清理，排版回归也向 4310 提交任务。先验证独立端口、数据库、素材、知识来源、凭据和输出目录，给脚本显式测试目标。用可恢复的数据库快照和媒体、知识文件、渲染输入、音乐索引清单恢复一条代表作品。隔离演练用模拟渠道，视觉预检、LLM 和 TTS 也用离线或替身输入。 [数据目录](../lib/db.mjs#L6) · [备份](../scripts/backup.mjs#L6) · [恢复](../scripts/restore.mjs#L15) · [账号 E2E](../scripts/e2e-account-data.mjs#L3) · [排版回归](../scripts/layout-regression.mjs#L2) · [视觉预检](../lib/preflight.mjs#L63)
- **干净检出可运行是切换条件。** 正片入口静态引入当前分镜、Round 4 数据和 Round 5 头像演示依赖，样式也从本地 JSON 读入。相关文件在本机可读，其中 Round 4/5 数据未由 Git 跟踪。将生产入口与演示分开，给正片和封面显式传入任务输入，或先用独立工作目录过渡。用干净目录和版本化素材跑一条正片及两张封面，才能验证恢复环境具备新执行器。 [Remotion 入口](../engines/vibemotion/renderer/src/Root.tsx#L4) · [样式入口](../engines/vibemotion/renderer/src/engine/tokens.ts#L1) · [忽略规则](../.gitignore)
- **收敛按入口分步。** 先并行读取历史和新产物，再切新建默认，观察队列、用户复核和发布包。回退优先切路由并保留期间新增的数据。旧执行器退役前单独验收批量和历史兼容、文章生成及媒体恢复。真实写入授权另行决策，本方案的发布测试保持 dry-run 和模拟。

### 2. 固定页式与讲解式边界

| 决策 | 固定页式 | 讲解式 |
| --- | --- | --- |
| 内容和时钟 | 保留字段化页面、页序和关键帧。首批 4/5/6 页，以旧布局及 20/24/28 秒为参考，兼容具体旧版本的页序与转场。 | 以脚本、旁白与图解关系编排不等长场景，配音、分句字幕、音效和镜头用同一时间轴。 |
| 用户编辑 | 逐页预览、字段定位、对照和强调词，保留同批次复核及重渲入口。 | 按句或场景查看、编辑文案、来源、图解和时序。 |
| 风格和能力 | 五个旧主题 `archive / terminal / editorial / noir / earth`，另核对 PageFrame V2 自有 `palette`。 | 简洁、严谨工业、活泼动感。头像是可选能力，当前正片要求对应场景预留头像位且有音轨。 |

界面明确「编排方式」「生成确认」「视觉风格」。目前 `video_tasks.mode` 的 `auto/manual` 决定是否先确认分镜，应保留其语义，在契约中用独立字段区分固定页式和讲解式。编排方式变更时新建候选版。两种方式共享媒体与输入清单、任务状态、预检、审批、内容身份和发布记录。内容层的结构库、选题来源、知识引用和灵魂档案独立于渲染方式，复用时应保留已选结构及引用快照。 [现有人工模式](../server.mjs#L306) · [模板预设](../lib/templates.mjs#L49) · [旧 V2 页序与配色](../renderer/v2/template-check.js#L18) · [来源和结构上下文](../lib/knowledge.mjs#L315) · [头像限制](../engines/vibemotion/renderer/src/Video.tsx#L164)

### 3. 旧 spec 字段级迁移

迁移输入优先用保存的实渲输入和审批记录，再用 spec 及当时的模板、品牌和素材快照补齐。旧执行器会在开渲时根据 Brief 重套模板并重新选元素，直接转换当前 `spec_json` 可能与原片不同。支持的旧版本、模板和字段应有确定的转换规则，保留原字段和异常报告。 [旧版输入快照](../server.mjs#L382) · [历史迁移提案脚本](../scripts/spec-migration-dryrun.mjs#L89)

| 旧字段或输入 | 可自动处理 | 需要人处理 |
| --- | --- | --- |
| `content_schema_version`、`renderer`、`template_id`、`page_count`、`theme`、`palette`、`motion` | 普通版、Hybrid、PageFrame V2 按已确认的实现分别解读。保留页序、预览采样、配色、转场和元素速度参数。 | 3 页、V2 自有色板、未知版本或冲突参数先登记，决定保留原件或增加迁移样本。 |
| `page1.cover.lead/punch`、`page1.lines/highlight`、`cover_v2` | 保留双段封面、原文和可唯一定位的强调词。已知的旧封面兼容规则可重用。 | 封面拆分不明、高亮多义、换行改变含义、超安全区时由人复核文案和预览。 |
| `page2.left_*`、`right_*`、`conclusion_*`、`structure_fields` | 映射左右对应、结论和事实结构，沿用已知上下/左右/对角原语规则。 | 缺一侧、来源冲突或字段歧义时定位并复核。 |
| `context`、`page3`、`evidence`、`objection`、`quote` | 按具体 renderer 和页数确定页角色，避免把 `page3` 按名字机械变成第三页。兼容已知旧字段与安全换行。 | 证据或语义缺口、旧页样式冲突、新稿需改写时复核。收尾按当前末页 CTA 规则验收，历史原片按原件读取。 |
| `article`、来源、`_meta`、结构快照 | 保留正文、小节、摘要、来源、系列及附篇字段，作为渠道变体关联同一内容版本。 | 核对需要补充的来源、渠道文案及素材许可。审批同时指向实际送出的文章/发布包版本。 |
| `music`、`elements`、音频、字体、审片记录 | 解析已知的素材 ID、版本与混流参数，保留有效输入。旧审批、发布回执和内容身份关联原产物。 | 缺失素材、未知许可、旧录音复用或改变渲染内容时复核。重新渲染的产物重新审批。 |

用转换前后逐字段差异、关键帧和例外清单验收。版式按 `AGENTS.md` 检查 4/5/6 页 × 五主题，覆盖 P1 封面和 P2/P3/P4、80% 安全区、正文 ≥24px、辅助说明 ≥28px、末页右下角 CTA、内部标签不可见及一个主强调。另验证较长中文、页切换、配乐和音频路径。既有 15 组报告可作对照，其样本同源且只覆盖历史预览布局。 [旧封面和对照字段](../renderer/render.mjs#L197) · [旧 P3 字段](../renderer/render.mjs#L316) · [旧 V2 页面实现](../renderer/v2/template-check.js#L18) · [历史排版报告](layout-regression-15.md) · [版式规则](../AGENTS.md)

### 4. 10–18 人日的估算

**10–18 人日可作受限范围的初估。** 假设原成片可继续查看，首批支持已确认的旧模板与五主题，按内容和流程等效验收。发布与任务地基、讲解式自动生成、历史异常数据处理、额外渠道联调和逐帧历史复刻另行估算，共用接口只计一次。旧 V2 的 FFmpeg 路径未混入音轨，批量重渲/复核与常规单条路径行为不同，先盘点使用范围再确认上限。方案中各阶段若串行合计为 9.5–19.5 天，属于另一种排期口径。 [原工时口径](ACTION-PLAN.md) · [旧 V2 输出](../renderer/v2/render.mjs#L108) · [批量操作](V1-USER-GUIDE.md)

| 固定页式里程碑 | 初估 | 验收 |
| --- | ---: | --- |
| 常用四页原型 | 2–3 人日 | 旧稿与新片逐页可比，字段改动能重渲，封面和混流可复看。 |
| 转换与共同产物接入 | 2–3 人日 | 一条旧稿可按版本转换，预检可定位，工作台能找到正确产物并审批。 |
| 五/六页、五主题与质量回归 | 4–7 人日 | 15 组通过，加代表性长文、上传音乐、批量预览/审批及回退样本。 |
| 历史访问、试切和退役检查 | 2–5 人日 | 原成片与旧回执可查，已支持稿件可按需迁移，文章路径和回退可独立验证。 |
| **合计** | **10–18 人日** | 四页验收后，按实际历史分布和测试结果复估。 |

阶段 1 的 1–3 天可先评估发布关口和错版止血。旧、新、批量三条执行路径的持久化、恢复和回归需要单独估算，完成条件以测试结果判断。

### 5. DSH 的发布边界与任务一致性还需补的内容

1. **保留历史发布事实。** 旧包按 `render_id + channel` 重用记录，改选题账号会更新关联发布记录，旧 dry-run 还会改状态、账号和回执。发布意图与账号、渠道、动作及版本绑定，账号或动作变更形成新记录。dry-run 只记演练结果。手工「标记已发布」应校验原记录、版本和回执，补录历史也要保留来源。旧数据中含义不明的 `published` 应显式列入核对清单。 [旧发布包及人工回执](../server.mjs#L1428) · [修改账号](../server.mjs#L1846) · [旧 dry-run](../lib/wechat.mjs#L215)
2. **在所有写入入口校验实际动作。** 拒绝缺失、错误或渠道不匹配的账号，移除「建草稿」里的自动提交。旧接口可请求关闭 dry-run，新接口使用默认账号并把草稿记为已发布。服务端按产物和渠道变体重查审批、预检和明确动作，测试环境拦住远程素材上传、草稿与提交。新发布包的 `channel` 直接参与路径构造，应使用允许列表并校验输出根目录。模拟丢响应后先核对远端结果，保留未知状态，按操作写入持久回执。视频号仍人工发布。蚁小二当前工作台可验证的是本地预检与配置，另有可发请求的适配函数，真实渠道联调独立排期。 [公众号调用](../lib/wechat.mjs#L205) · [新发布接口](../server.mjs#L1936) · [第三方预检](../server.mjs#L1606) · [蚁小二适配器](../lib/publishers/yixiaoer.mjs#L30)
3. **地基覆盖旧单条、旧批次和新任务。** 旧重渲会复用 `renderId` 和目录，审批保存哈希但发布不重新核对该快照。批量审批与单条审批的入口也不同。新任务改稿保留旧配音及发布状态，取消只是先改状态，后续执行仍可回写。用内容版本、尝试 ID 和不可变产物 ID 管住领取、取消、重试、错误、预检和最终提交。批量操作按具体产物审批。改稿使依赖旧文字的音轨、分镜和审批退出当前候选版，原始上传音频保留为素材，复用时重新核对和对齐。测试运行中改稿、取消后晚到、重复重试、交错渲染、重启和已审版本重渲。 [旧重渲复用](../server.mjs#L521) · [单条审批](../server.mjs#L1236) · [批量审批](../server.mjs#L1353) · [新任务执行](../server.mjs#L280) · [新任务编辑和取消](../server.mjs#L1903)
4. **质量检查进入服务端关口。** 旧预检按固定采样时刻并要求音轨，V2 的音频特征和讲解式场景时钟需要不同规则。新引擎出片后直接完成，现有草稿/打包入口也没有同等审批校验。共用视频解码、封面真实格式/尺寸、素材引用和内容检查，对版式、字幕和转场按页/场景采样。对已审文章、手工包和封面核验哈希及文件存在。缺失或阻断项需要明示，人工复核结论带版本与理由。 [现有预检](../lib/preflight.mjs#L125) · [新渲染和封面](../lib/vibemotion.mjs#L178) · [旧审批入口](../server.mjs#L1236)

### 6. 工作台入口

| 入口 | 人做的决定 | 系统负责 |
| --- | --- | --- |

| 发布与恢复 | 明确渠道、账号、版本和动作。对照摘要确认，按需回填实际链接或核对未知回执。 | 展示公众号文章预览、手工包内容及演练标记。按状态提供可用操作，保留历史回执与取消/重试结果。 |

样片 A 脚本测量的是**分句音频文件**的真实时长。导入整段录音仅测总时长无法证明逐句对齐，阶段 2B 要接受时间码或提供对齐和人工校对入口。优先以原片保留为历史策略，对需要续作的项目按需转换。 [样片 A 构建与字幕](../scripts/build-sample-a.mjs#L9) · [现有人工确认](../server.mjs#L1983)

## 四、建议的最终执行顺序

| 顺序 | 负责人建议 | 交付和通过条件 |

## 五、最容易出错的三点

1. **演练、换账号或重新打包改写历史。** 两个模拟账号对同一产物分别生成草稿意图，加入已发布回执、空链接、错渠道及响应丢失样本。验证已知回执的账号、版本和状态仍可还原，待核对动作仅由明确回执推进。
2. **看过的成片和最终发出的文件不同。** 单条、批量、新任务都按不可变产物提交。检查同时改稿、换主题或重试时，旧进程无法覆盖新成片，审批匹配视频、封面、字幕及渠道正文版本。
3. **本机样片成功后直接切换并退役。** 以干净目录渲染、隔离恢复、旧模板矩阵、历史媒体和独立文章路径验收，切默认和退役分别作决定。使用支持配置的隔离脚本，生产账号及本地 4310 不参加演练。
