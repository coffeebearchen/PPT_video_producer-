# 爆款不是被一条视频验证出来的

## 一个关于钩子、结构和发布次数的概率模型

---

## 一、先说结论

爆款不是一条视频的“属性”。

它更像一个结果：

```text
一个足够好的钩子
× 一个可复用的结构
× 足够多的有效尝试
× 一次被分发的机会
```

这句话有道理，但它不是严格定律。

它可以写成一个概率模型，但不能保证预测爆款。

更准确的说法是：

```text
你不能保证自己做出爆款
你只能提高自己遇到爆款的概率
```

---

## 二、把这句话翻译成数学

设：

```text
h = 钩子命中率
s = 结构稳定率
d = 分发命中率
N = 发布次数
```

单条视频“具备被推开的条件”的概率：

```text
p = h × s × d
```

至少一条成功的概率：

```text
P(N) = 1 - (1 - p)^N
```

期望结果：

```text
E = N × p × E[M]
```

其中 `M` 是单条视频的结果量级，比如播放、涨粉、咨询。

---

## 三、为什么是 `1 - (1-p)^N`

一条失败的概率：

```text
1 - p
```

连续 N 条都失败：

```text
(1 - p)^N
```

至少一条成功：

```text
1 - (1 - p)^N
```

这就是“多试”的数学来源。

它不是玄学。

它是独立重复试验的基本公式。

---

## 四、代入数字

假设：

```text
h = 0.15
s = 0.70
d = 0.50
```

那么：

```text
p = 0.15 × 0.70 × 0.50 = 0.0525
```

单条视频：

```text
5.25% 概率具备被推开的条件
```

发布次数与“至少一条成功”：

| N | P(N) |
|---:|---:|
| 1 | 5.3% |
| 10 | 41.7% |
| 30 | 80.2% |
| 50 | 93.2% |
| 100 | 99.5% |

如果钩子从 0.15 提到 0.30：

```text
p = 0.105
```

| N | P(N) |
|---:|---:|
| 10 | 67.0% |
| 30 | 96.4% |

这就是“钩子重要”的数学解释：

```text
h 翻倍
p 翻倍
N 不变，成功概率显著上升
```

---

## 五、但它不是线性增长

`P(N)` 是凹函数。

从 1 到 10：

```text
+36 个百分点
```

从 90 到 100：

```text
+1 个百分点
```

所以：

```text
多发有用
但边际收益递减
```

而且每一条都有成本：

```text
制作成本
审片成本
账号疲劳
观众疲劳
```

不是：

```text
无限发 = 一定爆
```

而是：

```text
在 p 不变的前提下
N 增加，概率上升，但越来越慢
```

---

## 六、N 只能放大 p，不能创造 p

如果：

```text
h = 0
```

那么：

```text
N = 1000
```

结果还是：

```text
0
```

如果选题本身没有需求，钩子再花哨，也不会变成爆款。

如果账号被限流，`d` 接近 0，N 也没有用。

所以正确的顺序是：

```text
先修 h
再修 s
再修 d
最后才放大 N
```

---

## 七、爆款不是 0/1，而是重尾分布

上面的模型把成功当成“是/否”。

真实世界不是。

大多数视频：

```text
几百播放
```

少数：

```text
几万
```

极少数：

```text
百万
```

设：

```text
Y_i = B_i × M_i
```

其中：

```text
B_i ~ Bernoulli(p)
M_i ~ 重尾分布
```

总结果：

```text
E[total] = N × p × E[M]
```

但“至少一条大爆”：

```text
P(max Y_i > K)
```

这需要：

```text
p 不低
N 足够
M 的尾部足够厚
```

所以：

```text
N 增加的是“抽到”的机会
不是“每条都变大”的机会
```

---

## 八、这是贝叶斯探索吗

部分是。

上面的公式是频率派概率。

如果你不知道 `p`，你可以用贝叶斯方法更新判断。

把每个钩子看成一条“手臂”：

```text
先验：Beta(1,1)
每发一次，成功 +1，失败 +1
得到后验：Beta(α,β)
```

然后用 Thompson Sampling：

```text
从每个钩子的后验里采样
选当前采样值最高的那个
```

这叫：

```text
贝叶斯多臂老虎机
```

它解决的是：

```text
在不确定的情况下
如何分配下一次尝试
```

但它不解决：

```text
爆款本身是不是必然
```

而且这里的“成功”必须定义成代理指标：

```text
2 秒留存
完播
评论
关注
```

不是直接定义成“爆款”。

---

## 九、路径是必然的吗

不是。

原因有四：

### 1. p 不是常数

同一个钩子，今天有效，明天可能无效。

```text
观众疲劳
平台变化
竞争加剧
```

### 2. N 不是独立

同账号连发，流量会互相影响。

```text
不是 100 次独立抽奖
```

### 3. 成功不是同分布

每条视频的 `M` 不一样。

```text
一条大爆
可以抵掉 99 条普通
```

### 4. 存在上限

`h` 不可能无限提高。

`h ≤ 1`。

`P(N)` 也有上限。

---

## 十、天花板在哪里

钩子有上限：

```text
注意力上限
```

选题有上限：

```text
受众规模上限
```

形式有上限：

```text
平台品类上限
```

账号有上限：

```text
权重与信任上限
```

分发有上限：

```text
时间窗口与竞争上限
```

所以到某个阶段：

```text
继续加钩子
不会线性增加爆款率
```

会进入：

```text
边际收益递减
```

甚至：

```text
过度优化钩子 → 信任下降 → p 下降
```

---

## 十一、正确的操作协议

### 第一步：不要先扩 30 条

先做：

```text
同一个题
4 页 20 秒
5 页 24 秒
```

验证：

```text
信息密度
```

### 第二步：同一个题，3 个钩子

验证：

```text
哪一个前 2 秒留人
```

### 第三步：跑 10 条 traffic

验证：

```text
生产线是否稳定
```

### 第四步：只放大赢的钩子

不是放大所有钩子。

```text
赢的钩子
× 稳定结构
× 可控次数
```

---

## 十二、一句话总结

```text
爆款 ≈ 用足够多的有效尝试
去抽样一个
由钩子、结构、分发共同决定的
重尾分布
```

写成公式：

```text
p = h × s × d
P(至少一条) = 1 - (1 - p)^N
E(总结果) = N × p × E[M]
```

它不是保证。

它是：

```text
让你在概率上站到更有利的位置
```

---

## 十三、最重要的一句

```text
N 只能放大 p
不能创造 p
```

如果：

```text
h = 0
```

那么：

```text
N = 1000
```

结果还是：

```text
0
```

所以：

```text
先修钩子
再谈数量
先找信号
再谈爆款
```
