## 2. 本轮要解决的核心问题

## 3. 要做三件事（按顺序）

### A. 把样片 A 的效果接回“自动生成”

```text
现在平台自动生成用的是简化版分镜（lib/vibemotion.mjs buildTimeline），
和样片 A 的高质量 ChalkBoard 不是一个等级。

请把 ChalkBoard 的绘制/点亮/动效能力，
做成“自动生成也能调用的通用组件”，
让用户输入文案就能得到接近样片 A 的质量。
```

### B. 增加“丰富图形 + 动效”库

```text
不要每条片都靠流程图。请扩充并实际使用：

结构类：流程 / 循环 / 分支 / 树 / 层叠 / 金字塔 / 中心辐射
数据类：折线 / 阶梯 / 柱状 / 条形 / 面积 / 饼 / 环 / 数字滚动 / 甘特
叙事类：时间轴 / 对比 / 误区划线 / 三支柱 / 金句
动效：路径绘制 / 节点点亮 / 柱子生长 / 圈注 / 局部放大 / 卡片状态切换

同一文案，AI 应根据内容关系自动选不同图解，而不是固定套路。
```

### C. 增加“讲解模式”可选（重点）

```text
生成时让用户选一个讲解模式，模式控制整体风格：

1. 简洁型：
   元素少、留白多、动效克制，适合“讲清楚一件事”

2. 严谨型：
   图表/数据/步骤更完整，适合“论证、干货”

3. 动感型：
   动效更丰富、切换更有节奏、高亮更明显，适合“吸睛、引流”

要求：
- 同一个主题，三种模式出来的画面明显不同
- 模式只是改变“密度/动效强度/配色强调”，不改内容正确性
- 在 TimelineDSL 里用字段表达模式（如 mode: simple|rigorous|dynamic），
  渲染层读取后控制装饰、动效、配色
```
