## 1. 产品定义

这不是一个“AI 写文案 + 套模板”的工具。

它是一个**结构优先的内容引擎**：

```text
方向 → 结构诊断 → 人选结构 → 内容生成 → 视频渲染 → 人工审批 → 发布
```

产品真正积累的资产不是文案，也不是模板，而是：

```text
结构库
+ 人的判断
+ 使用记录
+ 效果反馈
```

---

## 2. 一句话价值

```text
把一个人的结构能力，变成一套可复用、可审核、可积累的内容生产系统。
```

---

## 3. 设计原则

### 3.1 结构先于文案

先决定“用什么结构解释世界”，再决定“这句话怎么写”。

### 3.2 人先于 AI

AI 给方案，人做选择。

```text
AI 不自动选结构
AI 不自动通过审批
AI 不自动发布
```

### 3.3 Spec 是合同

AI 输出结构化数据，不输出任意 HTML/CSS。

代码保证版式、时长、动效、渲染稳定。

### 3.4 结构要留痕

每条内容都要记录：

```text
用了哪个结构
结构快照
谁选的
什么时候用的
```

### 3.5 不做一次性内容

任何一页、一个动效、一条音乐，都应该能被下一次复用。

---

## 4. 角色

| 角色 | 做什么 |
|---|---|
| 结构主编（你） | 定方向、选结构、审边界、做最终判断 |
| AI 导演 | 诊断结构、生成角度、填 VideoSpec、提音乐/金句建议 |
| 渲染器 | 按 Spec 出帧、混音、编码 |
| 审批人 | 看片、核事实、核结构、通过/退回 |
| 发布运营 | 生成发布包、人工上传、回填链接 |

小团队可以一人多岗，但“选结构”和“最终通过”必须是人。

## 5. 信息架构

```text
工作台
├─ 总览
├─ 创作台（原选题）
├─ 审批
└─ 发布

内容资产
├─ 结构库
├─ 知识库
├─ 音乐库
├─ 素材库
└─ 灵魂档案

系统
└─ 设置
```

### 命名变化

```text
选题 → 创作台
类比库 → 结构库
```

理由：

- “选题”听起来像填表；
- “创作台”容纳“方向 → 结构 → 角度 → 文案”的完整过程；
- “结构库”比“类比库”更准确，类比只是结构的一种。

## 7. 主流程

```text
1. 写方向
2. AI 诊断 2–3 个结构
3. 人选一个
4. 生成 Brief
5. AI 在结构约束下生成角度
6. 人选角度
7. AI 生成 VideoSpec
8. 人改文案 / 选音乐 / 调页数
9. 渲染
10. 抽帧预检
11. 人工审批
12. 发布
13. 记录结构与效果
```

---

## 8. 结构诊断

### 8.1 输入

```text
方向
受众
必须出现
必须避免
可选：已有结构库
```

### 8.2 输出

```text
2–3 个结构方案
每个方案包含：
  类型
  标题
  源域 / 目标域
  映射表
  边界
  签名
  为什么适合
```

### 8.3 UI

```text
方向输入
→ 三个结构卡并排
→ 选中态整块荧光绿
→ 用这个结构创建
```

结构卡必须直接展示映射，不只展示标题。

### 8.4 失败处理

```text
结构库为空 → 用通用结构兜底
AI 超时 → 返回结构库中最接近的 3 条
没有合适结构 → 允许“先不选结构，直接创建”
```

## 9. 结构库

### 9.1 类型

```text
类比
对照
因果
误区
边界
清单
```

### 9.2 列表

每个结构显示：

```text
类型
标题
映射条数
使用次数
签名
```

### 9.3 详情

```text
映射表
边界
适用场景
来源
使用记录
相关结构
```

### 9.4 操作

```text
新建
编辑
归档
合并重复
从随手记整理
从 AI 诊断结果保存
```

### 9.5 结构不是句子

一个结构至少要有：

```text
2 条以上映射
1 条边界
1 句签名
```

否则只是“比喻”，不是“结构”。

## 10. VideoSpec 与页面角色

### 10.1 页面角色

| 角色 | 作用 | 时长 |
|---|---|---|
| hook | 3 秒内让人停下来 | 4–5s |
| context | 背景 / 误解 | 4–5s |
| contrast | A vs B | 5–6s |
| evidence | 证据 / 边界 | 5–6s |
| objection | 反例 / 异议 | 4–5s |
| quote | 金句 + CTA | 3s |

### 10.2 页数

```text
3 页：hook + contrast + quote
4 页：hook + context + contrast + quote
5 页：hook + context + contrast + evidence + quote
6 页：hook + context + objection + contrast + evidence + quote
```

### 10.3 音乐

```text
BGM 全程铺底
没有独立音乐页
```

### 10.4 版式注册表

```text
hook → HookLayout
context → ContextLayout
contrast → ContrastLayout
evidence → EvidenceLayout
quote → QuoteLayout
```

AI 只能选角色和填 blocks，不能写任意版式。

## 11. AI 导演合同

### 11.1 输入

```text
方向 / Brief
结构快照
知识库片段
音乐库标签
页数约束
```

### 11.2 输出

```json
{
  "page_plan": ["hook", "context", "contrast", "evidence", "quote"],
  "pages": [],
  "music_suggestion": {},
  "quote_candidates": []
}
```

### 11.3 校验

```text
页数 3–6
角色合法
blocks 必填
文案长度
映射与结构一致
没有禁用词
```

### 11.4 失败回退

```text
LLM 失败 → 本地模板 + 结构快照
结构缺失 → 使用通用结构
页面失败 → 保留 Spec，人工编辑
```

## 12. 创作台 / 编辑器

### 12.1 结构锁定

顶部固定：

```text
已锁定结构：xxx
类型 · 映射数 · 第 N 次使用
```

### 12.2 右栏

```text
当前结构
映射表
边界
签名
换结构
保存并生成
```

### 12.3 页面编辑

按角色展示，不按“第 1 页/第 2 页”：

```text
hook
context
contrast
evidence
quote
```

每页只填 blocks：

```text
kicker
line1 / line2
highlight
body
note
cta
```

## 13. 审批

### 13.1 结构检查

```text
这条内容是否围绕选定结构？
映射有没有断裂？
有没有越过边界？
结论是否从结构里长出来？
```

### 13.2 事实检查

```text
来源
知识库引用
禁用表达
平台规则
```

### 13.3 机器预检

```text
关键帧
技术检查
视觉警告
```

视觉问题只警告，不替人通过。

保留：

```text
纸张底色

荧光绿

```

新增核心组件：

```text

BoundaryBox        边界
Signature          一句话签名
LockBar            结构锁定条

```

设计优先级：

```text
结构 > 文案 > 装饰
映射 > 比喻

```

## 18. 验收标准

### Phase 1

```text
1. 新建选题能诊断 3 个结构
2. 人选一个后 Brief 里有结构快照
3. 生成角度带结构约束
4. 结构库能按类型筛选
5. 使用次数 +1
6. 旧 v0.6 快照不动
```

### Phase 2

```text
1. VideoSpec 能校验
2. 4 页能渲染
3. 五个版式都能单独出图
4. 金句页可插拔
5. 审批页能看到结构
```
