## 0. SOP 是什么

SOP = Standard Operating Procedure，标准作业程序。

它不是产品说明书，也不是功能清单，而是回答：

```text
谁，在什么时候，按什么顺序，做什么，做到什么标准，出了问题找谁。
```

这份 SOP 的目标：

- 让一个新人照着做，也能产出一条可审批的视频；
- 让审批的人知道该看什么、不该看什么；
- 让发布的人知道哪些能自动、哪些必须人工；
- 让技术维护知道哪里不能碰、出了问题怎么回退。

一句话：

```text
AI 负责起草，人负责拍板；平台负责记录，人负责发布。
```

## 1. 角色与权限

小团队可以一人多岗，但建议把“制作”和“审批”分开。

| 角色 | 主要职责 | 不能做什么 |
|---|---|---|
| 主编 / 审批人 | 定选题方向、审事实、审合规、最终通过/退回 | 不看片直接通过 |
| 运营 / 制作 | 建选题、改文案、选角度、渲染、生成发布包、回填链接 | 自己审批自己发布（尽量分开） |
| 技术维护 | 启动服务、备份数据库、恢复版本、检查密钥 | 改冻结版本、把密钥发到群里 |

硬规则：

```text
AI 不发布。
AI 不审批。
AI 不直接覆盖已保存的灵魂档案。
发布前必须有人看过完整视频。
```

```text
双击 start.cmd
或

```

打开：


### 2.2 看三个地方

1. **总览**
   - 待审批：今天优先处理；
   - 发布队列：有没有卡住的任务；
   - 最近内容：有没有“需重渲”的旧片。

   - 已发布有没有缺链接、缺回执的。

## 3. 生产一条内容：主干流程

```text
建选题 → 选角度 → 生成文案 → 改文案 → 预览 → 渲染 → 审批 → 发布
```

### 3.1 新建选题

路径：

```text
左侧「选题」→ 右上「+ 新建选题」
```

推荐用 AI 预填：

1. 在「先给一个方向，AI 帮你填表」写一句方向；
2. 点「AI 预填表格」；
3. 逐项审核并修改；
4. 点「创建并生成角度」。

方向要写清楚三件事：

```text
给谁看
打破什么误解
最后落到什么结论
```

例子：

```text
给已经买 NAS 的内容创作者看：解释为什么自动化发布要放云服务器，
用邮局寄信做类比，结论是 NAS 管存稿、云上管发稿。
```

提交前检查：

- 标题：不超过 30 字，有具体对象；
- 话题：一两句，不是关键词堆砌；
- 受众：具体人群，不是“所有人”；
- 类比方向：1–3 个日常物件；
- 必须出现：关键结论；
- 必须避免：绝对化、未证实政策；
- 语气：冷静、具体；
- CTA：自然，不乞求关注；
- 渠道：视频号 / 公众号至少选一个。

### 3.2 加资料源（建议）

在选题详情「资料源」里点「+ 加资料」。

标准：

```text
每个关键结论，至少有一条来源。
没有来源的结论，不进脚本。
```

至少放一条官方来源或一手资料；没有来源时，审批要更严格。

### 3.3 选角度

在「角度卡」里看 3 张卡：

- 哪张最像你要说的话；
- 哪张有具体场景，不是空泛观点；
- 哪张的类比能落到技术结论。

点一张卡选中。  
不满意点「换一批」，但不要无限换；换两次还不满意，回去改 Brief。

### 3.4 生成三页文案

选中角度后，点：

```text
生成三页文案
```

生成后进入「三页文案」编辑区。

### 3.5 改文案

编辑区按页折叠：

```text
第 1 页 · 钩子
第 2 页 · 对照 + 结论
第 3 页 · 音乐页
视频音乐
公众号 · 图文
```

改稿标准：

- 每页只放一句人话；
- 第 1 页 3 秒内让人知道“这跟我有关”；
- 第 2 页有对照，不是两个形容词；
- 结论具体，能被复述；
- 脚注不写空话；
- 第 3 页不是凑时长，要有信息或情绪落点；
- 公众号图文不是视频字幕的复制。

### 3.6 选动效、转场、BGM

展开「视频音乐」：

| 项 | 建议 |
|---|---|
| 动效 | 日常 `Flow`；强节奏内容 `Strong`；不确定先 `Flow` |
| 转场 | 横向推页最稳；上翻页适合“翻篇”；下翻页适合“压下来” |
| BGM | 科技/效率 `Pulse 120`；叙事/冷静 `Minimal 80`；也可选已上传曲目 |
| 高级 JSON | 不懂就不要动；动之前先预览 |

「自动选曲依据」会显示为什么选这首；不对就手动改 BGM。

### 3.7 保存文案

点：

```text
保存文案
```

保存后，旧成片会标记为「文案已改」，必须重新渲染才能审批。

### 3.8 生成预览帧

点：

```text
生成预览帧
```

看三张预览：

- 文字有没有溢出；
- 标题有没有被裁；
- 信封/卡片位置是否合理；
- 颜色对比是否够；
- 三页是否像同一套东西。

预览不对，先改文案，不要直接渲染成片。

### 3.9 渲染成片

点：

```text
渲染成片
```

等待完成。  
当前一条 18 秒视频大约需要几分钟，取决于机器。

渲染完成后：

- 看视频，不只看封面；
- 听声音，确认有 BGM、没有爆音；
- 看转场，确认没有闪白、黑帧、半张旧页面；
- 看最后一帧，确认停得住。

## 4. 审批 SOP

路径：

```text
左侧「审批」→ 待审批 → 点开一条
```

### 4.1 先看视频

必须完整看一遍，重点：

- 前 3 秒有没有钩子；
- 中段有没有具体对照；
- 转场是否突兀；
- 音乐是否盖过人声/字幕；
- 最后一页是否记得住；
- 有没有明显错位、裁切、闪烁。

### 4.2 再对五条清单

全部勾选才能通过：

```text
1. 事实有出处
2. 平台规则已核对
3. 无绝对化 / 违规表述
4. 音乐 / 字体可商用
5. 标题 / 封面 / 描述齐全
```

### 4.3 看三个辅助区

- **来源**：关键结论能不能对上；
- **知识库引用**：这一版到底用了哪些片段；没有引用要警惕；
- **公众号图文**：标题、摘要、Lead、小节、CTA 是否完整。

### 4.4 看禁用表达

如果出现红色提示：

```text
命中禁用表达：保证、百分百、一定……
```

默认退回。  
除非确认这是引用、反例或有明确上下文，否则不要放行。

### 4.5 通过或退回

**通过**：

- 五条全勾；
- 视频完整看过；
- 没有未解释的禁用词；
- 点「通过」。

**退回**：

- 在批注里写清楚：
  - 第几页；
  - 哪个元素；
  - 改成什么；
  - 为什么。
- 点「退回修改」。

批注例子：

```text
第 2 页结论太虚，补一句“NAS 替代不了固定出口”。
第 3 页音乐太满，换成 Minimal 80。
```

不要写：

```text
再改改。
感觉不对。
```

## 5. 发布 SOP

路径：

```text
左侧「发布」
```

### 5.1 视频号

1. 在「待创建任务」找到已通过成片；
2. 点「视频号包」；
3. 生成后打开：
   - `video.mp4`
   - `cover.png`
   - `metadata.json`（标题/描述/标签）
4. 打开视频号助手，手动上传；
5. 发布完成后，回到发布页；
6. 点「标记已发布」，填视频号链接；
7. 确认「已发布」列表出现这条。

标准：

```text
视频号没有官方内容发布 API，最后一步必须人工。
```

### 5.2 小红书

1. 点「小红书包」；
2. 拿 9:16 成片 + 3:4 封面 + 标题/标签；
3. 在小红书后台手动发布；
4. 回填链接；
5. 标记已发布。

### 5.3 公众号

1. 点「公众号」创建任务；
2. 在队列里点「创建草稿」；
3. 如果开了 dry-run，只模拟，不真正调用；
4. 打开公众号后台检查草稿；
5. 确认排版、封面、摘要、CTA；
6. 发布，或由已配置的自动提交完成；
7. 回填文章链接；
8. 标记已发布。

标准：

```text
第一次正式发布前，先在公众号后台配好 IP 白名单。
不要在没有 dry-run 的情况下直接点发布。
```

### 5.4 发布台账

「已发布」列表就是当前台账：

```text
标题 / 渠道 / 状态 / 时间 / 链接
```

当前没有播放量、点赞、关注等效果数据；这些需要后续人工回填或接平台接口。

至少每周一次，重大改动前必须一次。

当前备份位置：


```text

```

备份文件含公众号/模型凭据，按敏感文件保管，不要发群、不要进 git。

### 6.2 检查音乐库

```text
设置 → 音乐库
```

- 删除不用的上传曲目；
- 补分类、BPM、标签；


## 7. 异常处理

### 7.1 页面打不开

1. 看服务是否在运行；
2. 重新双击 `start.cmd`；
3. 仍不行，看命令行报错；
4. 不要重装，先看日志和端口。

### 7.2 渲染失败

1. 看任务状态和错误提示；
2. 检查 Chrome / ffmpeg 是否可用；
3. 重新生成预览帧；
4. 仍失败，保留错误原文，找技术维护。

### 7.3 审批后文案又改了

系统会把旧成片标记为「文案已改」。  
必须重新渲染、重新审批；旧审批自动失效。

### 7.4 发布链接填错

回到「发布」→ 找到任务 → 重新标记已发布，覆盖链接。  
不要直接改数据库。

### 7.5 数据库损坏

1. 停止服务；
2. 备份当前 `data/studio.db`；
3. 用最近的 `backups/.../studio.db` 恢复；
4. 启动后跑 `npm run smoke:v0.5`；
5. 确认数据后继续。

### 7.6 想回到 v0.5

```powershell
cd D:\AI数字资产\studio\releases\v0.5.0
npm install
New-Item -ItemType Directory -Force data
Copy-Item ..\..\backups\v0.5.0\studio.db data\studio.db
npm start
```

不要用快照直接覆盖当前 `data`，除非确认要回到 v0.5 的数据状态。

## 9. 一条视频的验收标准

```text
内容：一句话能说清，结论具体，有来源
画面：三页不溢出、不裁切、不重叠
动态：有入场、有转场、有持续运动，不像 PPT
声音：有 BGM，不爆音，不盖字幕
审批：五条清单全勾，视频完整看过
发布：渠道正确，链接回填，台账有记录
```

## 10. 最短路径卡片

```text
1. 选题 → 新建选题 → 写方向 → AI 预填 → 审核 → 创建
2. 选角度 → 生成三页文案
3. 改文案 → 视频音乐（动效/转场/BGM）→ 保存
4. 生成预览帧 → 看三页
5. 渲染成片 → 完整看一遍
6. 审批 → 五条全勾 → 通过
7. 发布 → 视频号包 / 小红书包 / 公众号
8. 人工上传 → 回填链接 → 标记已发布
```
