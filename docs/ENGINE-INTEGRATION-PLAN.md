## 4. 三种接入方案对比

### 方案 1：在当前平台做「引擎适配器」（推荐）

```text
保留现有平台
新增 engines/ 模块
统一接口：
  render(video) → mp4 + cover + 状态 + 日志
```

优点：

```text
素材/音乐/知识/结构库直接复用
审批/发布包/账号组不用重写
回滚简单
```

缺点：

```text
需要抽象接口
两套引擎并存，维护量增加
```

### 方案 2：复制一份代码到新文件夹，替换视频引擎

```text
不推荐
```

原因：

```text
数据库、素材、音乐、账号组都要复制/同步
两套平台容易不一致
后期合并成本高
```

### 方案 3：删掉现有引擎，只保留新引擎

```text
风险最高，暂不推荐
```

原因：

```text
现有引擎是白盒、稳定、可控
新引擎黑盒、待验证
先并行，验证通过再决定去留
```

## 5. 推荐架构

```text
brief / spec（现有字段）
        │
        ▼
引擎选择
  ├─ 引擎 A：本地模板（现有 renderer/render.mjs）
  └─ 引擎 B：新 AI 引擎（engines/new-video/）
        │
        ▼
统一输出
  mp4 + cover + preview + 日志
        │
        ▼
现有审批 → 发布包 → 公众号/视频号
```

数据字段建议：

```text
brief.engine = 'template' | 'new_ai'
render.engine = 'template' | 'new_ai'
render.engine_config = { ... }
```

默认策略：

```text
新功能先用「新引擎」单独测试
老内容继续用「本地模板」
跑通后再允许批量切换
```

## 6. UI 改动建议（最小改动）

```text
创作台：
  新增「视频引擎」选择
    ○ 本地模板（现有）
    ○ AI 生成（新引擎）

审批页：
  显示引擎标识
  · 本地模板 / · AI 生成

发布页：
  不需要大改
  仍走发布包 / 公众号草稿

设置页：
  新增「视频引擎」配置卡
    新引擎地址 / Key / 参数
```

菜单建议：

```text
不新增一级菜单
在「创作台」内加引擎选择
在「设置」内加引擎配置
```

原因：

```text
素材库、音乐库、知识库、结构库不变
引擎只是生成方式，不是内容资产
```

## 7. 素材复用映射

| 现有资产 | 引擎 A | 引擎 B（需确认） |
|---|---|---|
| 文案 spec | 直接使用 | 转成提示词/脚本 |
| 音乐库 | 直接合成 | 提供音频或提示 |
| 封面 | 模板生成 | 提供图或生成 |
| 结构库 | 决定页型 | 提供结构提示 |
| 品牌色 | CSS token | 提供配色提示 |

如果新引擎不接受这些输入，就退化为：

```text
只把「最终文案 + 品牌提示词」交给它
生成后做统一质检
```
