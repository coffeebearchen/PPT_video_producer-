# 统一行动方案（DSH × Codex × 用户 三方综合）

> 依据：DSH《GLOBAL-REVIEW-DSH.md》+ Codex《GLOBAL-REVIEW-CODEX.md》。
> 结论：不重写项目，不先加新引擎/付费数字人；先收紧“发布边界、任务一致性、自动样片闭环”。

## 一、三方共识（先做这 3 件）

```text
1. 发布边界可信
   - 草稿 ≠ 已发布；草稿与正式提交拆成两步，账号必选
   - 视频号继续手动上传
   - 发布记录：账号/渠道/产物版本/media_id/链接/幂等键

2. 任务版本与取消可信
   - 改文案 → 旧配音、旧审批、旧发布准备全部失效
   - 取消要真的终止渲染；重试/重启有明确状态机
   - 完成回写校验 attempt，旧 attempt 不能覆盖新版本

3. 平台自动样片闭环
   - 修空稿写作短路、两场景、整段字幕、第0帧封面
   - 接真实配音时长 + 分句字幕 + 8–12 场景
   - 先打通 5–7 种常用图解自动选型，不一次上 45 项
```

## 二、明天执行顺序

| 序 | 动作 | 谁做 | 验收 |
|---|---|---|---|
| 0 | 汇总两清单，存基线/快照，定测试策略（禁止真实发送） | DSH 主导，用户确认 | 可回退基线 + 测试账号策略明确 |

| 3 | 自动质量：空稿写作、配音时长、分句字幕、8–12场景、封面双尺寸 | Codex 渲染 + DSH 对接 | 平台新建出一条接近样片A，可改可重渲 |
| 4 | 统一内容脉络 + 成片库/审批/发布覆盖两引擎 | DSH | 同一内容一个工作项，两引擎都能走到发布 |
| 5 | 目录/素材引用统一，配音选择/导入，头像校准入口 | 双方 | 目录与生成一致，删除不破坏项目 |

## 三、先不做的（明确延后）

```text
- 大规模表迁移/重建数据库
- 多用户、鉴权、公网暴露
- 付费精确数字人
- 45 项图形一次全部随机启用
- 一次性把老页面全部删掉（先做正确契约，再收敛页面）
```

## 四、对 DSH 原清单的校正（接受 Codex）

```text
1. “声音要分组归档” → 已实现；真正缺口是“任务引用 + 导入配音 + 资源生命周期”
2. “凭据接口返回Key” → 不准确；接口已脱敏，风险是本地明文存储+备份复制
3. “音乐要分组归档” → 降为次要；先做任务引用与导入配音
4. 样片质量差距 → 直接原因是空稿短路/两场景/硬编码文案/第0帧封面
```

## 五、如果明天只能做三件

```text
发布边界 → 任务版本与取消 → 平台自动样片闭环
（导入配音 + 统一 publication/attempt 关联，随这三件一起落地）
```

## 六、引擎收敛（用户提案，Codex 已评估同意）

```text
最终只保留 VibeMotion 作为视频渲染引擎，
把旧引擎能力做成「固定页式」模式。
```

- 模式 = 决定如何编排页面、编辑字段、预览
- 风格 = 决定配色、字体、视觉表现

### 旧引擎值得保留的 3 项能力

```text
1. 可控品牌页式（4/5/6 页构图、逐页文案、封面强调、对照收束）
2. 先看页面再出片（逐页关键帧预览、换主题预览、字段级编辑、批量复核）
3. 可定位质量检查（断句/文案完整/布局问题定位/成片预检，带入审批）
```

### 迁移顺序

```text
1. 先补共同契约（审批/发布绑产物版本，任务取消/重试/恢复，独立渲染输入）
2. 迁一条常用 4 页作品验证（逐页预览 + 文字 + 封面 + 混流 + 进审批）
3. 补齐 5/6 页和五主题（含公众号配图依赖）
4. 先切新建默认走 VibeMotion，再退旧执行器（历史项目保留原成片）
```

### 工作量（Codex 估算）

```text
约 10–18 人日（发布/任务一致性修复另计）
旧 spec 转换 + 独立输入 + 统一产物接口：2–3 人日
4/5/6 页组件 + 主题 + 动效迁移：4–7 人日
逐页预览/封面/音乐/质检接入：2–4 人日
视觉回归 + 历史兼容 + 分批切换：2–4 人日
```

### 前置条件

```text
发布边界 + 任务一致性 是正式切换的前置条件。
固定页式 4 页原型可并行做，等共同流程验收后再切默认入口。
```
