# 涂鸦视频流动感接入草案

状态：**待用户确认；本轮仅提交文档与审看证据，未实施渲染器改动。**

代码基线：已执行 `git pull --ff-only origin feature/courseware-dynamicflow`，当前 `bb1c759`。已阅读 `docs/DSH-SYNC.md`；该文档页首仍列较早提交号，本草案以实际拉取的 bb1c759 为准。

## 1. 本轮建议：先接通三项能力

1. **转场**：提取旧 SlideVisual 的转场外壳，保留 fade / slide / push / wipe 的算法；doodle 用自己的 Page 绘制函数接入同一外壳。
2. **字幕**：DoodleCourseware 调用 `subtitleCues + activeSubtitle`，增加唯一的项目级字幕层，移除 DiagramPage 固定3150ms显示 caption 的职责。
3. **图元同步**：按语义组安排框、标签、连线和点亮；cues 足够且有明确映射时使用 cues，否则消费 nodeTimings / bulletTimings。先补齐 model.ts 的类型、验证与保留。

画法继续使用用户的45种布局；新色板、hatch、DoodleVignette、固定种子、已新增的 DoodleCover 和平台功能均保持。首轮不增加复杂镜头、共享元素变形、物理粒子或字母翻牌。

流动感主要来自**保留已知信息，按讲解增加一个状态，再把视线带到下一处**。不少变化发生在同一场景内部，整页转场只是其中一部分。

## 3. 已确认的代码缺口

| 位置 | 当前事实 | 本轮处理 |
|---|---|---|
| Courseware.tsx 的私有 SlideVisual | 转场算法闭包里固定调用旧 Page | 提取转场外壳，注入视觉页；不能仅导出后直接用于 doodle，否则会画回旧页型 |
| DoodleCourseware.tsx | Sequence 直接渲染 Hero / DiagramPage，未消费上述转场 | 增加 DoodleSlideVisual，音频仍放在视觉转场之外 |
| DoodleCourseware.tsx | 播 narration，但未建立全局 cues 字幕 | 项目级统一读取当前字幕 |
| DiagramPage.tsx | 路径、标签、点亮分别用固定时间公式；caption 固定3150ms后出现 | 有同步计划时改用计划；无计划保留兼容回退 |
| model.ts | Slide / validateResolved 未保留 nodeTimings、bulletTimings | 类型与运行时验证、复制一并增加，不能只加类型 |
| lib/courseware-compile.mjs | flow / bullet 有旁白时才生成这两个时序数组；diagram 分支当前只复制 layout/data | 保留已有输出；diagram 通用语义组需要额外绑定，不能声称编译层已生成全部图解时序 |

编译层现有 cues 是按标点与字数估算；nodeTimings / bulletTimings 是按旁白时长均分。后者可能比句级 cues 更细，但并不代表真实词级对齐。渲染器先忠实消费冻结时间；更精确的对齐结果由平台后续提供。

## 4. 转场：复用旧 SlideVisual 的计算与裁剪

### 4.1 提取范围

建议新增 `PageTransition.tsx`，从旧 SlideVisual 提取：

- effectPlan 的 transition 时间窗与现有平滑插值；
- fade / slide / push / wipe、方向、位移和 clipPath；
- `Freeze(previous.durationInFrames - 1)` 的前页静帧机制。

通过 `renderPage({slide, first, last, ghost})` 注入视觉页。旧 SlideVisual 作为薄封装继续传旧 Page；doodle 的薄封装传 Hero / DiagramPage / 媒体视觉页。旧模式不改变转场参数或数学公式。

转场只包含视觉。前页 ghost 不包含旁白、BGM、sfx或第二套字幕。前页按自己的数据和时序计划冻结到末帧；字幕只显示当前全局 cue。

`effects.transition` 的字段沿用现有模型，不另发明转场类型。首轮示例可显式给 doodle 页加 fade 300ms；没有该字段时保持当前直接切页行为，不擅自给历史稿加默认效果。

### 4.2 三个必须处理的边界

1. 转场占用当前页已有入场区间，不更改 fromFrame、durationInFrames 或音轨起点。cue 不因转场自动后移；若开头需要留白，应由平台冻结的声音与 cues 一起体现。
2. 背景和 DoodleVignette 保持稳定，避免安全区裁剪后外围暗角突然消失、或者前后两页叠出双重暗角。建议由 doodle 项目外壳只画一次；独立 DiagramPage/Hero 预览保留默认暗角，通过内部参数避免套两层。
3. 新增 DoodleCover 继续使用 Hero 的 still 状态，不经过视频的入场转场，不回到动画第0帧的空白状态。

## 5. 字幕：项目级单一所有者

在 DoodleCourseware 的项目时钟上：

```ts
const frame = useCurrentFrame();
const {fps} = useVideoConfig();
const cues = useMemo(() => subtitleCues(project), [project]);
const cue = activeSubtitle(cues, frame, fps);
```

字幕放在各页 Sequence 和 PageTransition 外面，位置仍在竖屏逻辑画布内部；颜色取 C.ink / C.surface，黑体取现有 FONT。

保持 model.ts 现有语义：

- 明确提供 cues：按冻结时间显示，区间为 start包含/end不包含；
- `cues: []`：明确关闭字幕，不再从 caption 补回来；
- cues 缺省且有 caption：沿用 subtitleCues 的兜底；
- narration 播放、BGM/sfx 保持各自现有时间，不放入 ghost。

DiagramPage 不再把 slide.caption 当成一条固定晚出现的画面文字，避免与全局字幕重复。source 的 foot 可继续用于无字幕的独立样图预览；正式视频中的说明句如需保留，应通过明确的正文槽位安排，不能占用字幕带。

混排页面也必须只渲染一份全局字幕，不能同时保留递归子项目的字幕。媒体 trim/mute/loop 和 image contain/Ken Burns 不变。

## 6. 同步：保留字段，再按语义组消费

### 6.1 原字段格式保持不变

拟在 Slide 增加的可选字段：

```ts
type NodeTiming = {
  id: string;
  startSeconds: number;
  endSeconds: number;
};
type BulletTiming = {
  startSeconds: number;
  endSeconds: number;
};
// Slide
nodeTimings?: NodeTiming[];
bulletTimings?: BulletTiming[];
```

字段均为可选，保持 courseware/1 的旧缺省行为；不恢复未支持的 effects.textSync 默认值。

二者都是**相对本页的秒数**，不能直接当项目全局秒或毫秒。nodeTimings 按 id 找目标，bulletTimings 按原 bullets 下标对应。验证后复制到返回的 Slide，保持序列化可往返。

验证建议：

- 有限数值，0 ≤ start < end ≤ 本页时长；不得越过页尾。
- 若同时限制旁白时长，允许编译层三位小数舍入误差，不能误拒绝已有输出。
- flow 的 id 必须来自本页 nodes，不能重复、悬空或缺失；bullet 非空时序数组长度必须与 bullets 一致。
- 缺省不填默认 timing；空数组保留并按“无可用时序”回退。显式提供的非空错误数据报错，不静默猜测。
- 初版 flow / bullet 按时间顺序且不重叠；图解中“总览已建立＋局部当前强调”的重叠由语义组状态处理，不用复制多套旁白轨道。

### 6.2 图解的“组”不是一条 SVG path

框、标签、关联连线必须归入稳定组。source.js 的 group 是绘图调用序号，只作为组内绘制信息，不作为跨版本语义身份。

首批适配当前48秒样片的6种图解：

| 布局 | 拟注册的语义组键 | 归组方式 |
|---|---|---|
| A02 | decision / success / failure | 判断节点；成功支路与文字；失败支路与文字 |
| B03 | nodes.0 … nodes.3 | 每个步骤的框、文字及对应方向提示 |
| B05 | lanes.0 … lanes.2 | 用户、Router、Worker各自前景内容与交接；基础泳道框可先保持弱可见 |
| D02 | request / reply / router / worker | 请求气泡、应答、路由职责、执行者 |
| C08 | grid.all / grid.active | 300个点的总览；同一坐标上的20个选中点 |
| B07 | before / after / change | 原路径、新路径、变化提示 |

在绘制适配中为 path/text 绑定语义组，不更换画法、文字内容、色板或随机种子。未适配布局继续原有排程；不能把任意45种图都按“第几个path”映射成节点。

diagram 的 nodeTimings 如要直接使用上述组键，需要按布局注册表验证；这些键可以含点号，不能套用 flow 节点 id 的旧正则。现有编译器尚未给 diagram 生成它们；首个验证片可使用手工冻结的 resolved props，平台是否增加传递/生成由 DSH 决定。

### 6.3 cues 怎样绑定语义组

不能仅凭 cue 数量或字幕字符串猜目标。建议评审一个最小可选字段，用于 diagram（以下为拟议契约，当前尚未实现）：

```json
{
  "cueGroupBindings": [
    {"cueIndex": 0, "groupIds": ["grid.all"]},
    {"cueIndex": 1, "groupIds": ["grid.active"]}
  ]
}
```

cueIndex 指向本页最终 cues 数组，groupIds 必须来自该布局注册表。编导明确想同时解释的少量相关组可以共用一个 cue；不能把数量不足的 cues 强行一对一分配。

本轮renderer可以先验证手工冻结数据；字段进入生产分镜/编译链须由 DSH 同步。不要在渲染器里硬编码“第二句话就是 Worker”。

### 6.4 时间来源优先级

1. **cues 足够并有有效语义绑定**：直接使用其时间窗。
2. **cues 不够细**：使用能覆盖所需目标的 nodeTimings / bulletTimings；diagram 按注册的组键消费 nodeTimings。
3. **缺少可用时序**：保留当前稳定默认排程。这是旧稿兼容路径，不标记为旁白同步。

一页先选定可用的时间来源，再生成只读计划；不为同一组混合两个相冲突的时钟。无配音的 demo 只能验证手工时序，不能据此验收语音对齐。

### 6.5 出现、当前强调和结束状态

- startSeconds：进入/绘制从此刻开始。
- 时间窗内部：当前组按原语义色强调，标签与框、连线共用同一事件时钟。
- endSeconds：当前强调退回正常状态，已经出现的内容保留；不能整组消失，不能重新绘制过去节点。
- 当前窗口短于默认绘制时长时，在窗口内缩短入场或直接显现，保证不拖到下一句；不改 cue 和旁白时间。
- 同步时间换算只做秒→局部帧；不受横屏比例、预览倍率或播放回溯影响。

C08 总量层由 grid.all 时间窗内按固定顺序建立；grid.active 点亮只遍历 activeIndices，20个点在该组窗口内依次亮起。group开始时间来自 cue/timing，窗口内插值仍可使用固定索引顺序。总量、点位和选中集合保持真实，结束不闪烁。

以6秒页为例：0–2秒建立300点，2–4.8秒解释并点亮20点，4.8–6秒完整保留供阅读。这是本项目候选排期，不是参考视频时码。

## 7. 横屏：在逻辑画布内做完，再缩放一次

平台刚增加的策略保留：1920×1080中居中放置1080×1920的竖屏内容，左右填底色，不改成横屏重排。

```text
s = 1080 / 1920 = 0.5625
xOffset = (1920 - 1080 × s) / 2 = 656.25
实际内容宽 = 607.5
screenX = 656.25 + logicalX × 0.5625
screenY = logicalY × 0.5625
```

逻辑安全区 x108–972 / y192–1728，对应横屏 x717–1203 / y108–972。

### 7.1 转场与背景

- PageTransition 始终处理1080×1920逻辑坐标；旧的横向864、纵向1536位移和安全区裁剪先在内部完成，再由 LandscapeWrap 统一缩放。
- 不能把 useVideoConfig 返回的1920宽直接当 doodle 内部动画位移；也不能把逻辑坐标先乘s后又套CSS缩放。
- 新增项目层必须有明确1080×1920逻辑尺寸，避免 percentage/AbsoluteFill 意外以已经缩小的包装盒为尺寸。
- 两侧填色不随内容滑入/擦除；DoodleVignette 保留在竖屏内容范围，不擅自改变平台侧边填色。

### 7.2 全局字幕位置与可读性

“全局”指整个项目一层；字幕仍在同一逻辑画布中，不在1920宽的侧边区域重新画一份。

竖屏沿用当前字幕带。横屏32逻辑px实际只有18px，因此建议本次全局字幕按画幅补偿到**实际至少24px**：逻辑字号 `max(32, ceil(24/s))`，横屏为43px。字幕仍位于竖屏安全区；补偿后按最多3行预留高度，避开CTA，超长cue需缩短/拆分，不压到字号下限。

这是草案中建议确认的一项具体取舍：保持当前横屏居中策略，同时单独保障新增字幕层的输出可读性。其它已经随平台缩放的文字不在本轮重新排版。

平台0.5倍低清预览只缩输出像素，不改变 cue 时间、行文内容或动画计划。字号补偿按项目画幅计算，不按预览倍率反复改布局。

### 7.3 混排页避免第二次 LandscapeWrap

当前 DoodleCourseware 对 image/video/screenshot 等页递归调用带完整项目包装的 Courseware。横屏下可能再次进入 LandscapeWrap；单页子项目还会把自己当末页，产生重复CTA/字幕上下文的风险。

转场接入时应复用**纯视觉页入口**，并从外部传 isFirst/isLast/ghost 与完整项目上下文；LandscapeWrap、项目字幕、Soundtrack只由最外层拥有。这个适配在 renderer 内完成，不动平台入口。
